# Orbit

> **每个人都可以训练自己的本地模型。**

Orbit 是一个本地 AI 工作室，把模型训练、checkpoint 管理、对话和 OpenAI 兼容 API 集中在同一个界面中。默认情况下，训练数据、模型和对话都保留在用户自己的电脑上。

## 结构如下

自研的 `orbit-hybrid-moe-v1` 架构：

```text
Plain text
  ↓
UTF-8 字节输入
  ↓
256 字节词表 Embedding
  ↓
多层 Orbit Backbone
  ├─ DepthResidual 深度残差
  ├─ DeltaAttention 自定义注意力
  ├─ GatedMLA 潜变量注意力
  ├─ RMSNorm
  └─ LatentMoE 稀疏专家网络
      ├─ 8 个路由专家
      ├─ 每个 token 激活 Top-2
      ├─ 1 个共享专家
      └─ SiTUGLU 门控前馈网络
  ↓
共享 Embedding 的语言模型输出头
  ↓
预测下一个 UTF-8 字节
```

公开模型边界见
[`Orbit模型文档/Orbit模型文档.md`](Orbit模型文档/Orbit模型文档.md)。详细的
内部架构技术报告保存在公开仓库之外。

## 项目边界

这是公开的 **Orbit** 项目。**Orbit-PC** 是 Orbit 的电脑版主线，负责本地训练、推理、桌面 App、模型和 OpenAI
兼容 API。**Orbit-XR** 是 YUNSH OS 内置的系统集成表层，单独归入
[`Orbit-XR`](https://github.com/ljcccc999/yunsh-os)；**Orbit-Phone** 是
iPhone/HarmonyOS 手机版，单独维护。三者的源码、模型、发布版本、Logo 和
硬件测试结果严格分开，不把 XR 或 Phone 的能力混入 Orbit-PC；Phone 和 XR
都是配合 YUNSH OS 使用的表层。

Orbit 由三层组成：**架构层**（OCA 与 `orbit-hybrid-moe-v1`）、**训练层**
（数据、参数和验证）以及**表层**（Orbit-PC、Orbit-Phone、Orbit-XR）。
文件和项目边界见 [Orbit 三层架构项目文档](Orbit三层架构项目文档.md)。

## Orbit 三层入口

- **架构层：** [OCA](Orbit模型文档/OCA-项目文档.md)（尚未实现完成的世界模型研究架构）与
  [`orbit-hybrid-moe-v1`](Orbit模型文档/orbit-hybrid-moe-v1-项目文档.md)。
- **训练层：** [训练方式与参数数据](Orbit训练方式与参数数据.md)。
- **表层：** **Orbit-PC** 是电脑版主线；[Orbit-XR](https://github.com/ljcccc999/yunsh-os)
  与 Orbit-Phone 都是配合 YUNSH OS 使用的表层，随 YUNSH OS 项目维护。

## Orbit 可以做什么

- 提供可拖动的桌面工作台，并把对话、模型、训练、训练历史和 API 分成独立区域。
- 默认跟随操作系统语言，也可手动切换 English / 中文。
- 提供约 300M 到 38B 参数的架构预设。
- 把本地训练作为核心流程：每个人都可以使用自己的文本选择模型规模，在自己的电脑上训练，并在之后继续训练。
- 分配模型前检查本机内存。
- 在 macOS、Linux 和 Windows 上运行可崩溃恢复的后台 API。
- 关闭窗口后仍在 macOS 菜单栏或 Windows/Linux 系统托盘常驻；只有选择“退出 Orbit”才停止本地服务。
- 按需加载模型；空闲五分钟后自动卸载权重并释放加速器缓存。
- 可使用 DeepSeek 或其他 OpenAI 兼容 API，根据所选模型参数生成监督数据并自动进入本机训练；每个提供商分别保存模型、地址和 API Key，更换一个 Key 不影响其他提供商。
- AI 辅助生成后可以在训练页直接查看完整语料、滚动浏览和复制；训练历史中也会保留并明确标注这份教师 AI 生成内容。
- 训练数据可选择中文、English 或数量均衡的中英双语。
- 可为共同模型创建便携贡献包；内容先进入待审核或隔离区，未经本机人工批准不会进入训练数据。
- 根据模型规模、训练设备、当前可用内存以及本机或教师样本的数据量自动调整高级训练参数；本机无法安全完成的配置会在分配内存前阻止启动，并建议生成远程 GPU 任务包。
- 原来的参数优化选择会直接显示平衡、省时间、省内存和效果优先四组具体推荐结果，包括步数、序列长度、预计时间、峰值内存和样本数。
- 人工训练和 AI 辅助训练使用同一种在本机生成的 GPU 训练包；训练包可以下载，也可以直接导入用户配置的 Orbit 训练服务器。
- 将本机训练的 checkpoint 保存在 `~/.orbit/models`。
- 支持自定义模型名、从已有 checkpoint 二次训练、父模型血缘，以及查看每次训练的原文、参数和结果。
- 用户自定义的显示名称与 checkpoint 的内部唯一 ID 分开保存，即使文件名需要加时间戳后缀，Orbit 界面也不会把后缀编号当成模型名称。
- Orbit 的不可变产品身份是“Orbit，由 YUNSH 开发”，独立于用户自定义模型名和训练文本；即使还没训练模型也知道自己是谁，服务器导出包也会保留这个身份。
- 在本机生成包含数据集、配置、源码、身份规则和 `run.sh` 的自包含 CUDA GPU 训练包。
- 可把训练模型导出为带 OpenAI 兼容 API 的便携 Orbit 服务器；存在兼容的同名 GGUF 时也可生成 Ollama 包。
- 通过 `GET /v1/models`、`POST /v1/chat/completions` 和 `POST /v1/responses` 提供本地模型 API。
- 可生成多个随机、可撤销的 API Key，并把每个 Key 限定到某一个本地模型。
- 让本机智能体通过 OpenAI 兼容配置接入。

## Orbit Code

点击左上角产品切换器，可以在 **Orbit**、**训练** 和 **Orbit Code** 之间切换。Orbit Code 是本地优先的编码 Agent：执行前先说明方案，执行中报告新发现，结束时给出结果与验证总结。

- 左侧把“插件”直接放在“新对话”下方；对话历史使用摘要标题，运行中的对话显示转圈，完成后仍可展开查看以前的完整执行过程。
- 输入栏支持文件、图片和语音。任务运行时，新消息默认排队；点击“改变位置”后会成为立即引导，但不会停止原任务。撤销排队消息需要确认，提升为引导后不可撤销。
- 输入栏上方用液态玻璃圆环显示已完成步数/总步数与当前活动；绿色新增和红色删除统计均可点击进入文件审核。
- 执行过程可展开三层，同时保留 Agent 直接显示的阶段说明。运行中第一层显示当前正在思考、查询代码、运行命令、编辑文件或操作鼠标键盘；完成后自动变为已编辑文件数、已搜索网页次数等汇总。展开后第二层列出该阶段所有已完成和正在执行的动作；再展开具体动作，第三层显示完整 Shell 输出、搜索内容、鼠标键盘结果或红绿 diff。修改文件还可在 App 右侧查看完整内容；已删除文件显示修改前归档。
- “智能”不是装饰标签：级别越高，可用的 Agent 轮数、搜索、检查、验证、执行时间和输出 token 越多。系统保持稳定指令前缀与只追加的任务历史，以提高支持该能力的 API 的提示缓存命中率。
- 权限包括“请求批准”“替我批准·工作区”和“完全访问”。越界或危险操作仍经过本地权限流程。“允许操控鼠标和键盘”是默认关闭的独立开关：Agent 优先使用文件、API 和命令行，只有没有可靠程序化路径且确有必要时才操作界面；每次尝试都会显示在执行时间线中。
- 关闭桌面窗口后，Agent 与本机 API 继续在后台运行；只有右上角状态菜单中的“退出 Orbit（停止 Agent 与 API）”才会结束后台 Agent 并释放本机 API 端口。设置中可选择工作时不让电脑休眠，以及是否登录时自动运行后台服务。
- 每个任务都使用稳定的 Agent 系统提示词：明确 Orbit Code 是由 YUNSH 开发的 Orbit 产品，并规定规划、证据、安全、执行、验证和结果汇报方式。
- API 页面支持本地 Orbit、OpenAI、Anthropic、Gemini、DeepSeek、xAI、Groq、Mistral、OpenRouter 和自定义 OpenAI 兼容接口，可保存多个配置且不显示完整 Key。若兼容接口拒绝可选 OpenAI 字段，会自动用基础字段重试一次。
- 本地插件通过 `plugin.json` 导入并按设备启用，在新任务中加入插件说明；插件动作仍服从 Orbit Code 的同一套权限。

## 运行要求

- 系统内存必须大于 10GB；更大的模型需要更多内存。
- macOS、Linux 或 Windows；正式训练建议使用 CUDA。
- 用户不必提前安装 Python。安装器会使用合适的现有 Python，或自动准备隔离的 Python 3.11 运行时。
- 首次下载安装器和依赖时需要联网。完成后，训练、推理和本机 API 可以离线运行。

## 一行安装并启动

### 桌面 App

下载最新的 [macOS 通用 App](https://github.com/ljcccc999/orbit/releases/latest/download/Orbit-macOS-universal.zip)、[Windows x64 App](https://github.com/ljcccc999/orbit/releases/latest/download/Orbit-Windows-x64.exe)、[Windows ARM64 App](https://github.com/ljcccc999/orbit/releases/latest/download/Orbit-Windows-arm64.exe)、[Linux x64 AppImage](https://github.com/ljcccc999/orbit/releases/latest/download/Orbit-Linux-x64.AppImage) 或 [Linux ARM64 AppImage](https://github.com/ljcccc999/orbit/releases/latest/download/Orbit-Linux-arm64.AppImage)。双击 App 后会在图形界面中自动准备本机运行时，不需要打开命令行。

首次启动后，Orbit 会随用户登录自动运行。关闭或最小化窗口时，Orbit 会继续留在 macOS 右上角菜单栏、Windows 通知区域或 Linux 系统托盘中，本地 API 保持可用。只有从该菜单选择“退出 Orbit”，才会停止 API 并取消自动启动；以后手动打开 Orbit 会重新启用。

左下角更新区域现在分为两个按钮：“检查更新”只检查官方 Release；“立即安装”会在 App 内下载、校验并排队安装最新版本。如果正在训练，安装会等待安全 checkpoint 保存后再重启本机服务；模型、对话、API Key 和训练历史仍保留在用户自己的数据目录中。

当前公开构建还没有 Developer ID/Authenticode 正式签名和公证，因此 macOS Gatekeeper 或 Windows SmartScreen 在首次打开时可能要求用户明确确认。彻底去掉系统提示需要对应平台的代码签名证书，程序代码不能安全绕过。

### macOS 与 Linux 命令行

```bash
curl --retry 5 --retry-delay 2 --connect-timeout 20 -fsSL https://raw.githubusercontent.com/ljcccc999/orbit/main/install.sh | sh
```

安装器会检查内存，在 `~/.orbit/runtime` 创建隔离运行环境，安装 Orbit，启动本机服务并打开浏览器。以后执行 `orbit` 即可再次打开。网页只是管理客户端，关掉网页不会停止 OpenAI 兼容 API。

下载中断后可以安全地重新执行同一条命令。安装器会继续使用已有的隔离环境，并自动重试网络下载。

Orbit 默认只监听 `127.0.0.1:8765`，不会暴露给局域网或互联网。

```bash
orbit start
orbit status
orbit chat "你好"
orbit unload
orbit stop
```

macOS LaunchAgent 和 Linux 用户级 systemd 服务会在 Orbit 异常退出后重启。`orbit unload` 可立即释放当前模型；不手动执行时，默认空闲计时器也会自动卸载。

## 模型规模

| 预设 | 近似参数量 | 保守训练内存估算 | 适用环境 |
| --- | ---: | ---: | --- |
| 300M | 0.308B | 9.9GB | 性能较好的个人电脑 |
| 1B | 1.063B | 34.0GB | 大内存工作站或 GPU |
| 3B | 2.969B | 95.0GB | 工作站或多 GPU 服务器 |
| 7B | 7.179B | 229.7GB | 多 GPU 服务器 |
| 14B | 14.075B | 450.4GB | 分布式训练系统 |
| 38B | 38.260B | 1,224.3GB | 大型分布式 GPU 集群 |

这些是包含优化器状态和工作内存的保守完整训练估算。实际需求会受到精度、优化器、激活检查点、分片、序列长度和硬件的影响。

## 训练

打开“训练”页面，选择预设，可选填写模型名或选择父 checkpoint，粘贴自己的文本，然后选择训练方式：

- **预训练（从零开始）**使用随机初始化的 Orbit 权重；**微调**可以继续训练已经训练过的本地 Orbit，也可以输入 HTTPS 地址下载并验证兼容的 Orbit checkpoint，再把它加入基础模型列表。页面会区分本地模型和下载模型，并保留父模型训练血缘。Orbit 不会把用户选择的模式静默改成另一种。
- 人工文献会根据 UTF-8 语料大小和序列长度显示估算样本数；页面会提醒数据过少、过拟合、上下文过长、内存压力过高或预训练目标不现实，并给出更安全的参数建议。
- 四种参数优化目标会根据实际 token 预算、模型规模、设备和内存推荐参数；AI 辅助每轮支持 1～10,000,000 个样本，这是防止误触造成 API、磁盘和内存失控的运行上限，不是完整预训练语料。用户手动填写的数量不会被推荐值悄悄覆盖；更大的语料应分轮生成、查看、去重和审核。人工文献和 AI 语料可以合并在同一次训练中，已完成或中断前的教师原文仍可单独查看。统一训练说明见 [`Orbit训练方式与参数数据.md`](Orbit训练方式与参数数据.md)。
- 重置后，高级参数会使用一套内部一致的**平衡**建议，不再用临时样本数算出与最终样本数不匹配的步数。用户可以单独修改高级参数，四套建议不会因此变化；重新选择方案或点击“重新应用当前建议”即可恢复整套推荐值。

Orbit 会分开显示三种不能混用的单位：**样本**是教师 AI 返回并通过检查的一篇独立文献/任务；当前 `orbit-byte-v1` tokenizer 中，一个**训练 token**就是一个 UTF-8 字节；一个**步**是完成 batch 与梯度累计后的一次优化器更新。因此字符数、字节数、训练 token 和优化器步数会分别显示。教师批次必须带严格样本边界，并通过语言、长度、控制字符、完全重复和近重复检查；格式错误会重试，只有真正接受的样本才增加进度。系统会按样本确定性隔离 5% 验证集，不让它参与权重更新。结构检查不等于事实核验，所以界面会明确显示“事实尚未独立审核”。

规模上，从随机权重预训练是基础模型工程，不是普通本机聊天微调。按 Chinchilla 每参数约 20 token 的规划参考，300M/1B/3B/7B/14B/38B 分别约需 **60 亿、200 亿、600 亿、1400 亿、2800 亿、7600 亿 token**。这些是规划参考，不是质量保证，也不规定固定样本数或固定优化器步数；步数应按实际 token、序列长度、Batch、梯度累计和遍历次数计算。界面还会显示 Llama 3 报告中约 37 token/参数的规模实例作对照，但它不是通用目标。真正可行的聊天路线是选择已经完成基础预训练且格式兼容的基础模型，再做高质量 SFT；LIMA 的 1,000 条精心筛选样本可作为研究起点，不是所有领域的最低要求。更大的 AI 语料在每轮 10,000,000 条安全上限下分轮生成、审核和训练。

训练页现在把“本轮最终结果”和“研究标准”分开显示。最终优化器 token 覆盖量按 `步数 × 序列长度 × Batch × 梯度累计` 计算；例如改成 2000 步、序列 512、Batch 1、梯度累计 1，就是 **1,024,000 token**。旁边会显示所选规模的参考标准（300M 约 **60 亿 token**）和偏差百分比；偏差越接近 0%，越接近这个预训练参考。四个目标仍然保留，打开训练页默认是“平衡”；手动改高级参数只更新当前结果，不会偷偷修改模型架构，也不会改写四套目标建议。微调会显示当前覆盖量，但不会把预训练的统一 token 标准硬套到 SFT。

页面会分开显示人工训练建议：预训练第 1～N 次都应以文献和代码为主，只在末尾加入少量对话/身份样本；微调应根据验证结果动态混合专业文献、单轮标注任务和高质量指令对话，不强制固定百分比。结构化任务包括分类/情感分析、NER、代码/SQL 生成、摘要总结、文本扩写/润色；它们是输入→输出样本，不是聊天气泡。外部或下载模型不能从随机权重开始训练，只能作为基础模型进入微调。

1. **在本机开始训练**：只有通过内存检查后才会启动本地任务，checkpoint 保存在 `~/.orbit/models`。
2. **在本机生成 GPU 训练包**：生成包含数据集、配置、Orbit 源码、身份规则和 `run.sh` 的 ZIP。人工训练和 AI 辅助训练使用相同格式；可以下载，也可以登录 Orbit Hub 后点击“在本机生成并导入服务器”，直接导入自己的训练服务器。
3. **生成样本并自动训练**：调用 DeepSeek 或其他 OpenAI 兼容教师 API，然后在本机开始训练。Orbit 会把所选模型的参数量、上下文长度、步数、父模型、用户目标和不可变身份规则告诉教师模型：模型是由 YUNSH 开发的 Orbit。每个自动生成的数据集还会在训练前加入真实的身份问答样本。样本数会影响数据覆盖面、生成时间和 API 费用。生成的数据集保存在本机。每个提供商的模型、地址和 Key 分别保存在 `~/.orbit/teacher-api.json`，权限仅限当前用户；切换回来会恢复原配置，输入新 Key 只替换当前提供商的旧 Key。Key 不会进入训练历史、服务器上传或导出包。训练目标会发送给提供商且可能产生费用，因此必须由用户明确确认。

每次实际训练都会在 `~/.orbit/training-runs` 保存可查看的记录，包括原始训练内容、参数、状态、loss、结果、模型名和父模型。点击“二次训练”会创建新 checkpoint 和新优化器，不覆盖父模型。

训练页面提供两个停止操作：“安全停止并保留 checkpoint”会保留可继续训练的中间模型；“停止并删除未完成模型”会删除未完成的 checkpoint 和元数据，但保留训练历史。

## 协作训练

“协作”页面允许任何人提交想法、事实资料或对话样本，并导出为 `.orbit-contribution.zip` 贡献包。其他用户导入后，内容会进入本机审核队列。机器预筛会隔离明显的危险操作指导或个人信息；事实材料必须附 HTTPS 来源，并由审核人明确确认已经核实。只有“已批准”的贡献才能汇总到训练文本。

自动筛查不能证明内容一定真实、合法。最终审核人仍需检查来源、内容权利、隐私和规则；被机器标记的内容不能直接批准。当前版本通过便携贡献包协作，不会在后台把内容静默上传到中心服务器。

完整审核流程与官方参考资料见双语 [协作贡献政策](COMMUNITY_POLICY.md)。

## 可选 Orbit Hub

`server/` 提供一个可选的小型服务器 Hub，用于账号、管理员审核、已完成模型上传和本机生成的 GPU 训练包导入。Orbit 在用户本机生成训练包，再通过分块上传和校验导入已配置服务器。Hub 只保存训练包，不会自动执行、加载或解析上传文件。部署方式和安全边界见 [server/README.md](server/README.md)。

300M–38B 表示 Orbit 的架构规模。训练页面可以通过 HTTPS 下载 Orbit checkpoint，验证架构后加入本地基础模型列表。当前 Orbit 的 byte-level 架构和训练器还不能直接加载 Hugging Face/Qwen 权重；要把 Qwen 作为微调基础模型，必须先完成真实的 tokenizer、模型架构和权重格式适配。要从零训练出真正可用的基础模型，需要大量经过认真处理的数据和可观的算力。

## 本地对话

训练完成后，打开“对话”页面直接发送消息，不需要手动加载。Orbit 会像 Ollama 一样自动选择并加载本机 checkpoint；推理不需要互联网连接。“新对话”只清除当前可见消息，不会删除模型或 Key。网页和桌面 App 关闭后，后台 API 仍可回答；如果模型因空闲被卸载，下一条消息会自动重新加载，因此第一次响应会更慢。

Orbit 身份会作为真实身份和对话样本加入第一次及后续每次训练，并跟随导出包。推理进程**不会**识别“你是谁”后用程序替换答案，也不会写死一条固定回复；导出 checkpoint 后能否正确回答，取决于模型真正学到的权重。很小或失败的训练仍可能答错，App 不能伪装成训练成功。

Orbit 当前使用实验性的字节级 tokenizer 和模型架构。很小或很短的训练只能验证流程，无法直接产生通用能力很强的助手。

## 导出与部署

模型页面提供两条明确的导出路径：

- **服务器导出**：生成包含 checkpoint、Orbit 身份元数据、源码、macOS/Linux 与 Windows 启动脚本和 OpenAI 兼容服务的 ZIP，可移动到用户自己的服务器。
- **Ollama 导出**：只有存在兼容的 `~/.orbit/models/<模型名>.gguf` 时才生成基于 GGUF 的 `Modelfile` 包。Orbit 实验性的原生 `.pt` 混合架构不会被伪装成 GGUF；这种格式应使用服务器导出。

## 接入本机智能体

打开“API”页面即可复制地址和示例。默认配置如下：

```json
{
  "provider": "openai-compatible",
  "base_url": "http://127.0.0.1:8765/v1",
  "api_key": "Orbit 页面显示的随机 Key",
  "model": "你的本地模型名称"
}
```

Python 示例：

```python
from openai import OpenAI

client = OpenAI(
    base_url="http://127.0.0.1:8765/v1",
    api_key="Orbit 页面显示的随机 Key",
)

response = client.chat.completions.create(
    model="你的本地模型名称",
    messages=[{"role": "user", "content": "你好"}],
)
print(response.choices[0].message.content)
```

Orbit 会校验每一个 `/v1` 请求。首次启动会创建第一个随机 Key；API 页面可以继续生成多个 Key，并限定为全部模型或某一个 checkpoint。撤销其中一个 Key 不会影响其他智能体。

API 按 OpenAI 的模型列表、非流式 Chat Completions 和非流式 Responses 请求/响应格式工作。把 OpenAI SDK 的 `base_url` 指向 Orbit 本地地址即可，调用这些接口不需要联网。

Orbit 不会自动上传本地训练文本、checkpoint 或聊天消息。只有用户明确选择导入服务器时，才会上传 GPU 训练包；教师 API Key 永远不会写入训练包。

## 更新

AI 辅助生成的训练内容预览区可以使用鼠标滚轮或触控板独立滚动，包括较大的教师语料。

打开“设置”，开启“自动更新 Orbit”。Orbit 会在后台检查官方发布。如果正在训练，更新会进入队列，等当前 checkpoint 保存完成后再安全重启本机服务。支持从较旧的、已经带有更新器的版本直接更新到最新版本，不需要逐个安装中间版本。

最初的 0.5.0 运行时还没有更新器，因此需要先手动安装一次较新的 Orbit；之后就可以在 App 内更新。

替换运行时和桌面 App 后，更新器会强制重新加载一次后台服务，并等待新服务恢复健康，避免旧 KeepAlive 进程在新版本号下继续提供内存中的旧界面。

## 私有开发协作空间

受邀请的开发者只能通过独立的 Orbit 项目协作空间参与开发、审核和测试。协作空间地址和访问权限由项目所有者另行提供。

这个公开 GitHub 页面不是开发者入口。开发者不会获得 GitHub 仓库、仓库 Secrets、Deploy Key、协作者、GitHub App 或 Release 权限。任何改动都必须经过项目所有者审核并明确接受后，才能发布。
