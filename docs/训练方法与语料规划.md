# Orbit 训练方法与语料规划

## 先判断训练类型

Orbit 的训练页必须明确区分两条路径：

- **预训练第 1 次**：从 Orbit 随机权重开始，主体是大量清洗后的文献、教材、技术资料、事实材料、代码和代码注释；只在末尾加入少量结构化任务、对话和 Orbit 身份样本。
- **Orbit 继续预训练第 2～N 次**：必须选择上一轮 Orbit checkpoint 作为父模型，继续使用文献/代码为主的语料；不能因为换了一轮就把数据集变成聊天记录。
- **微调**：必须选择已有 Orbit checkpoint 或真正兼容的基础模型，动态混合专业文献、标注任务和高质量指令对话，学习领域能力、指令遵循和输出格式。

外部模型不能从零训练。Qwen、Llama 等外部权重只有在 Orbit 完成真实 tokenizer、架构、权重格式和训练/推理适配后，才能显示为可用基础模型；在此之前只能使用 Orbit checkpoint，不能放置看似可用但实际无法加载的入口。

## 建议的语料组成

### 预训练第 1～N 次

不要把类别写成所有模型都适用的固定百分比。论文和公开训练报告没有给出“文献/任务/对话”对所有规模都通用的 80/10/10 配方。预训练应该先保证：

- 清洗、去重后的长篇文献、教材、科学/数学/逻辑资料、技术文档、事实材料、代码和代码注释覆盖主要 token；
- 结构化任务（分类/情感分析、NER、代码/SQL、摘要、扩写/润色）覆盖目标能力和输出格式；
- 交流、拒答、表达方式和 Orbit 身份只作为少量尾部样本，避免把预训练变成聊天记录复读。

实际权重应按去重后的 token 数、来源质量、主题覆盖率和独立验证集结果调整，并在 App 中显示当前各类 token 数。步数 × batch × 梯度累计只是优化器更新量，不等于高质量语料的遍历次数。

### Token 预算计算器

从零预训练的默认研究基线是 Chinchilla 的约 **20 个训练 token/参数**。Orbit 在界面中按名义模型规模计算，显示为中文大单位：

| 模型档位 | 20 token/参数的参考预算 |
| --- | ---: |
| 300M | 60 亿 token |
| 1B | 200 亿 token |
| 3B | 600 亿 token |
| 7B | 1400 亿 token |
| 14B | 2800 亿 token |
| 38B | 7600 亿 token |

Llama 3 报告还公开了一个约 405B 模型使用 15T token 的规模实例，约 37 token/参数。Orbit 把它显示为“论文对照”，不是所有模型都必须达到的固定目标。用户手动输入参数量或 token 数时只改变规划计算，不会偷偷把 300M 架构改成 38B。

教师 AI 每轮最多生成 10,000,000 条样本，这是防止误触导致 API 费用、磁盘和内存失控的运行上限，不是论文规定的语料规模。完整参考预算超过本轮上限时，应分多轮生成、查看、去重、审核并追加；每轮都保留原文和来源记录。

### 微调

- 保留目标领域专业文献、术语、事实材料和规范流程。
- 保留明确的单轮输入→输出任务，不使用聊天气泡包装。
- 保留高质量用户/助手指令对话，覆盖澄清、格式遵循、边界说明、拒答和 Orbit 身份。
- 不固定三类数据的百分比；先建立独立验证集，再针对表现最弱的类别补样、去重和质检。

微调样本需要有训练目标和验证集，不能只把同一小段文本重复很多轮。样本少、步数高、梯度累计大时，App 必须提示过拟合风险。

## 结构化任务格式

结构化任务不是普通聊天，建议每条包含任务类型、输入、输出格式和一个明确答案：

```text
任务类型：情感分析
输入：这手机电池太差了
输出：负面

任务类型：实体抽取（NER）
输入：我住在北京朝阳区
输出：北京（地名）、朝阳区（地名）

任务类型：SQL 生成
输入：查询年龄大于18岁的用户
输出：SELECT * FROM users WHERE age > 18;

任务类型：摘要总结
输入：一篇长新闻正文
输出：保留事实的约200字摘要

任务类型：文本扩写/润色
输入：报告写完了，很累
输出：保持原意的完整扩写或情感散文
```

## 辅助 AI 必须执行的检查

教师 AI 收到的请求必须同时包含用户训练目标、语料规划、训练类型、训练轮次、模型规模、语言、样本数和安全要求。它还必须：

1. 围绕目标生成内容，避免空话和模板循环。
2. 生成多主题、多措辞、多难度样本，并主动去重。
3. 不确定事实明确标注，不捏造来源、数据、法规和实验结果。
4. 代码尽量语法正确，SQL 说明表/字段假设。
5. 保持分类标签、NER 类型和输出格式一致。
6. 摘要不增加原文没有的事实，扩写不改变原意。
7. 不生成隐私、密钥、违法操作、危险教程或恶意代码。
8. 结构化任务保持单轮输入→输出；只有交流样本使用 user/assistant 格式。
9. 先生成文献和代码主体，最后追加少量结构化任务、对话和身份样本。
10. 把 Orbit 身份作为训练样本写入语料，不能在运行时写死回答。

## 设计依据

- Chinchilla 研究强调模型规模与训练 token 预算需要一起规划，不能只盯着参数量或步数：[Training Compute-Optimal Large Language Models](https://arxiv.org/abs/2203.15556)。
- Llama 3 报告明确区分预训练和多轮后训练，支持 Orbit 保留训练轮次与父模型血缘：[The Llama 3 Herd of Models](https://arxiv.org/abs/2407.21783)。
- StackLLaMA 展示了继续训练可使用因果语言模型目标处理领域文本，而不是把所有数据强行改成聊天：[StackLLaMA](https://github.com/huggingface/blog/blob/main/stackllama.md)。
- FLAN 与 Super-NaturalInstructions 说明多任务、明确任务定义和任务类型多样性有助于指令泛化：[FLAN](https://arxiv.org/abs/2109.01652)、[Super-NaturalInstructions](https://arxiv.org/abs/2204.07705)。
- QLoRA 说明量化基础模型加 LoRA 可以降低微调显存，但它需要真实兼容的 tokenizer、架构和权重适配，不能仅凭一个下载按钮假装支持：[QLoRA](https://arxiv.org/abs/2305.14314)。
- Chinchilla 的计算最优研究给出约 20 token/参数的规划基线，但不规定样本数或优化器步数：[Training Compute-Optimal Large Language Models](https://arxiv.org/abs/2203.15556)。
- Phi-1 说明高质量教材式数据对小模型代码能力很重要，数据质量不能由重复样本数量替代：[Textbooks Are All You Need](https://arxiv.org/abs/2306.11644)。
- LIMA 使用 1,000 条精心筛选的指令样本作为后训练研究基线；这不是所有领域都适用的最低或推荐条数：[LIMA](https://arxiv.org/abs/2305.11206)。
- Llama 3 的 15T/405B 是一个已发表的规模实例，适合用作数据丰富度对照，不应被误写为通用定律：[The Llama 3 Herd of Models](https://arxiv.org/abs/2407.21783)。
