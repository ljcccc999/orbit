# Orbit 训练方法与语料规划

## 先判断训练类型

Orbit 的训练页必须明确区分两条路径：

- **预训练第 1 次**：从 Orbit 随机权重开始，主体是大量清洗后的文献、教材、技术资料、事实材料、代码和代码注释；只在末尾加入少量结构化任务、对话和 Orbit 身份样本。
- **Orbit 继续预训练第 2～N 次**：必须选择上一轮 Orbit checkpoint 作为父模型，继续使用文献/代码为主的语料；不能因为换了一轮就把数据集变成聊天记录。
- **微调**：必须选择已有 Orbit checkpoint 或真正兼容的基础模型，使用专业文献、标注任务和约 50% 高质量指令对话，学习领域能力、指令遵循和输出格式。

外部模型不能从零训练。Qwen、Llama 等外部权重只有在 Orbit 完成真实 tokenizer、架构、权重格式和训练/推理适配后，才能显示为可用基础模型；在此之前只能使用 Orbit checkpoint，不能放置看似可用但实际无法加载的入口。

## 建议的语料组成

### 预训练第 1～N 次

建议总体按以下方向规划，而不是按“对话条数”规划：

- 约 80%：长篇文献、教材章节、技术文档、事实说明、代码、代码注释和推导过程。
- 约 10%：单轮结构化任务，包括分类/情感分析、实体抽取（NER）、代码/SQL 生成、摘要总结、文本扩写/润色。
- 约 10%：少量用户/助手交流、拒答范例、表达方式和 Orbit 身份样本。

预训练数据应按总 token 数和有效覆盖率规划。步数 × batch × 梯度累计只是优化器更新量，不等于高质量语料的遍历次数。

### 微调

- 约 25%：目标领域专业文献、术语、事实材料和规范流程。
- 约 25%：明确的单轮输入→输出任务，不使用聊天气泡包装。
- 约 50%：高质量用户/助手指令对话，覆盖澄清、格式遵循、边界说明、拒答和 Orbit 身份。

微调样本需要有训练目标和验证集，不能只把同一小段文本重复很多轮。样本少、步数高、梯度累计大时，App 必须提示过拟合风险。

## 结构化任务格式

结构化任务不是普通聊天，建议每条包含任务类型、输入、输出格式和一个明确答案：

```text
任务类型：情感分析
输入：这手机电池太差了
输出：负面

任务类型：实体抽取（NER）
输入：我住在北京朝阳区
输出：北京（地名）、朝阳区（地名）

任务类型：SQL 生成
输入：查询年龄大于18岁的用户
输出：SELECT * FROM users WHERE age > 18;

任务类型：摘要总结
输入：一篇长新闻正文
输出：保留事实的约200字摘要

任务类型：文本扩写/润色
输入：报告写完了，很累
输出：保持原意的完整扩写或情感散文
```

## 辅助 AI 必须执行的检查

教师 AI 收到的请求必须同时包含用户训练目标、语料规划、训练类型、训练轮次、模型规模、语言、样本数和安全要求。它还必须：

1. 围绕目标生成内容，避免空话和模板循环。
2. 生成多主题、多措辞、多难度样本，并主动去重。
3. 不确定事实明确标注，不捏造来源、数据、法规和实验结果。
4. 代码尽量语法正确，SQL 说明表/字段假设。
5. 保持分类标签、NER 类型和输出格式一致。
6. 摘要不增加原文没有的事实，扩写不改变原意。
7. 不生成隐私、密钥、违法操作、危险教程或恶意代码。
8. 结构化任务保持单轮输入→输出；只有交流样本使用 user/assistant 格式。
9. 先生成文献和代码主体，最后追加少量结构化任务、对话和身份样本。
10. 把 Orbit 身份作为训练样本写入语料，不能在运行时写死回答。

## 设计依据

- Chinchilla 研究强调模型规模与训练 token 预算需要一起规划，不能只盯着参数量或步数：[Training Compute-Optimal Large Language Models](https://arxiv.org/abs/2203.15556)。
- Llama 3 报告明确区分预训练和多轮后训练，支持 Orbit 保留训练轮次与父模型血缘：[The Llama 3 Herd of Models](https://arxiv.org/abs/2407.21783)。
- StackLLaMA 展示了继续训练可使用因果语言模型目标处理领域文本，而不是把所有数据强行改成聊天：[StackLLaMA](https://github.com/huggingface/blog/blob/main/stackllama.md)。
- FLAN 与 Super-NaturalInstructions 说明多任务、明确任务定义和任务类型多样性有助于指令泛化：[FLAN](https://arxiv.org/abs/2109.01652)、[Super-NaturalInstructions](https://arxiv.org/abs/2204.07705)。
- QLoRA 说明量化基础模型加 LoRA 可以降低微调显存，但它需要真实兼容的 tokenizer、架构和权重适配，不能仅凭一个下载按钮假装支持：[QLoRA](https://arxiv.org/abs/2305.14314)。
