# Orbit 易错与发布前检查清单

这份清单用于每次 Orbit 修改、训练、打包和发布前的回归检查。它记录的是已经出现过或必须重点防止的问题，不是功能宣传文案。

## 训练模式与数据

- [ ] 训练页必须明确显示“预训练（从零开始）/ 微调（基于已有模型）”选择器。
- [ ] 预训练必须显示第 1～N 次：第 1 次随机初始化；第 2 次及以后必须选择上一轮 Orbit checkpoint，记录 `training_round`、父模型和完整血缘，不能把继续预训练误标成微调。
- [ ] 预训练第 1～N 次以基础认知、多文献、教材、技术资料和代码为主，只保留少量对话/身份样本；微调按基础模型弱项和用户目标动态混合专业文献、结构化任务与高质量对话，不硬编固定百分比。
- [ ] 结构化任务不能全部包装成聊天气泡：至少覆盖分类/情感分析、NER、代码/SQL 生成、摘要总结、文本扩写/润色，并保存清晰的输入→输出目标。
- [ ] AI 辅助提示必须同时发送“语料规划”和用户训练目标；规划要包含模式、训练次数、模型参数、任务类型、语料配比、语言、样本数和安全身份规则。
- [ ] AI 辅助生成完成后，训练页必须能查看完整语料并复制；训练历史详情必须明确标注 AI 生成内容，不能只显示“已生成”状态。
- [ ] AI 辅助生成必须在每批教师 API 返回后立即追加保存到本地 partial 语料；余额不足、超时、断网、停止或服务重启时保留已完成部分，并提供继续/查看/删除入口，不能等 500 个样本全部完成后才第一次写盘。
- [ ] 人工训练旁边必须分别说明预训练和微调应该准备什么内容；用户自己提供的语料不会被静默替换成聊天记录。
- [ ] 切换到微调后，基础模型下拉框必须启用，并自动选择第一个本地 checkpoint；没有模型时必须明确提示“请先选择本地模型”，不能显示成“从零训练”并继续提交。
- [ ] 基础模型来源必须能切换“本地模型 / 下载兼容模型”；下载后要先验证 Orbit 架构，再加入本地列表，不能把 Qwen 等外部权重伪装成兼容模型。
- [ ] 微调时 M/B 模型规模必须锁定为所选基础模型的规模；界面禁用该选择，后端也拒绝不匹配请求，人工和 AI 辅助都不能偷偷改规模。
- [ ] 预训练和微调不能静默互相转换；请求中必须带 `training_mode`，微调必须带 `base_model`。
- [ ] 人工文献训练显示按实际语料估算的样本数；AI 辅助训练显示教师样本数，并解释样本数对覆盖面、时间、费用和过拟合的影响。
- [ ] 选择优化目标后，AI 样本数和人工文献建议字数必须同时更新；人工文献与 AI 语料可以合并进入同一次训练，AI 原文仍可单独查看。
- [ ] AI 辅助每轮上限为 10,000,000；它是防止误触导致 API 请求、费用、时间、磁盘和内存失控的运行保护，不是完整预训练规模。超过一轮时必须支持分轮追加，并提示去重、审核和额度风险，不能把“越多越好”解释成无需质量控制。
- [ ] 训练内容以用户提供的文献、技术资料和代码为主，不得静默读取历史对话或其他用户数据。
- [ ] 预训练和微调的人工内容建议必须分开显示，并随模式切换；AI 辅助提示也必须收到对应模式的语料配方，不能使用同一段泛化建议。
- [ ] 预训练建议基础认知为主体并覆盖教材、科学、数学、代码和结构化任务；微调使用研究驱动的动态混合，不得写死为固定对话比例，并明确验证集、去重和质量过滤。
- [ ] 研究依据和参数解释必须保存在 `docs/训练数据质量与参数建议-研究依据.md`，发布前检查界面文字与文档一致。
- [ ] 训练开始时记录模式、父模型、参数、数据语言、样本数、步数和配置；完成后按规则重置表单，训练中不能丢失草稿。
- [ ] 第一次训练和二次训练都要保留身份训练样本；不得把“你是谁”的最终回答硬编码成普通聊天逻辑。
- [ ] 训练目标为聊天机器人时，必须同时覆盖基础认知、上下文承接、多轮对话、指令遵循和自然表达；不能只用编程样本或把所有数据做成聊天气泡。
- [ ] 样本、字符、字节、训练 token、micro-batch 和优化器步数必须分开显示；一个样本绝不等于一步。当前 `orbit-byte-v1` 的 token 是 UTF-8 字节，不能冒充 BPE/SentencePiece token。
- [ ] 修改步数、序列长度、Batch 或梯度累计后，页面必须显示最终 token 公式、所选规模的研究标准和偏差；例如 2000 × 512 × 1 × 1 = 1,024,000 token，偏差越接近 0% 越接近预训练参考。
- [ ] 打开训练页默认必须是“平衡”；四个目标仍要保留。微调不能套用从零预训练的 20 token/参数标准，必须提示按验证集和过拟合判断。
- [ ] AI 样本必须有严格可解析的开始/结束边界；进度只按真正通过长度、语言、乱码、控制字符、完全重复和近重复检查的样本累计，不能按 API 请求数累计。
- [ ] AI 语料按样本确定性隔离验证集；同一篇文献不能通过随机窗口同时进入训练和验证。未实现自动 validation loss/early stopping 时要明确写“已隔离但尚未自动评估”。
- [ ] 教师 AI 的事实谨慎提示不等于事实核验；没有独立来源核对时界面必须显示“事实尚未独立审核”。
- [ ] 人工与 AI 语料合并后，训练 worker 必须读取合并文件；发布前用不同标记验证两部分都实际进入 worker 输入。
- [ ] 300M 随机权重从零预训练必须按 token 量级提示约 60 亿 token 参考目标和当前覆盖率；少量数据只能标记为流程实验，不能承诺正常聊天。
- [ ] 约 300M 的聊天 SFT 默认建议只适用于真正预训练且格式兼容的基础模型：最低 5 万、推荐 10 万、效果优先 20 万条；单次 5 万上限时分轮生成与训练，不能偷偷突破上限。

## 参数、内存与速度

- [ ] 根据模型规模、电脑可用内存、设备和语料量给出推荐参数，并在每个参数下说明对时间和内存的影响。
- [ ] 高级参数必须提供“省时间 / 省内存 / 效果优先（不计时间）”选项，并联动推荐样本数、步数、序列长度、梯度累计、checkpoint 频率；推荐结果要解释代价。
- [ ] 训练前保留至少 1 GB 系统安全余量；模型所需内存不足时按钮禁用并写明原因，同时提供远程 GPU 任务包入口。
- [ ] Apple Silicon 自动优先使用 MPS；不能无提示退回 CPU，除非没有可用加速器或用户明确选择 CPU。
- [ ] ETA 必须由实际训练速度校正；不能因为把 400 步改成 50 步仍显示旧的固定总时间。
- [ ] 训练过程显示步数、进度、loss、已用时间、预计剩余时间、内存和异常原因；初始化很慢时也要显示“正在初始化第 1 步”。
- [ ] 训练隔离进程异常退出（包括 -15）时保留可恢复 checkpoint 和明确状态；停止后必须能继续或删除未完成模型。

## 模型、对话与 API

- [ ] 模型加载后按钮必须变为“卸载模型”，未加载时显示“加载模型”；对话页和模型页状态一致。
- [ ] 模型空闲自动卸载，API 服务和轻量后台进程继续运行；关闭窗口不等于退出 API，只有明确退出 Orbit 才停止桌面 App。
- [ ] 删除模型、训练历史和归档对话的按钮必须真实可用，并保留正确的二次确认规则。
- [ ] 自定义模型名要在所有页面和 API 中一致，重复名称在开始训练前提示，不能显示内部默认字符串。
- [ ] 本地 API 必须兼容 OpenAI 格式；生成的 key 使用标准 `sk-` 格式或明确记录的兼容格式，且不在日志和 UI 中泄露完整教师 Key。
- [ ] 输入框不能自动把 `1+1`、问候或“你是谁”写成答案；只有用户点击发送或按 Enter 才能提交。
- [ ] 对话要支持新建、历史查看和归档；标题优先使用整段对话摘要，没有 AI 摘要时使用第一句话。

## App 与界面

- [ ] 白屏是最高优先级发布阻断项：检查生成页面的 `</style>`、`</body>`、主 `.app` 容器和 WebView 本地加载；必须实际打开 App 截图验证，不得只依赖 Python 编译或 CI 通过。
- [ ] Orbit、训练、Orbit Code 共用顶部产品切换器，但侧栏历史必须随工作空间切换；不得同时显示 Orbit 对话、训练历史和 Code 对话，也不得在 Orbit Code 内再嵌套第二条侧栏。
- [ ] 每个工作空间的侧栏顺序固定为“新对话/新训练 → 当前模式固定入口 → 当前模式历史”；协作只属于训练模式，不能出现在 Orbit 或 Orbit Code。
- [ ] Orbit Code 右侧只有一个主滚动容器；用户消息、阶段说明、执行动作、用时、文件统计和总结都在对话流内，输入栏固定底部，不能另放顶部执行面板或让多个滚动容器互相截断。
- [ ] 普通 Orbit 对话不显示重复的页内标题或右侧运行时检查栏；执行阶段收起时显示工具调用总数和动作分类，展开后显示每个工具与完整输出。
- [ ] 输入栏右下角常驻只显示当前模型；第一层弹出“智能”滑杆，点“高级”后才显示具体模型和速度，三层都使用同一套液态玻璃材质并支持减少透明度。

- [ ] macOS、Windows、Linux 都必须有对应启动方式；macOS App 启动显示 Logo 和加载动画，窗口可拖动、可关闭到后台并可从右上角菜单退出。
- [ ] 训练页必须可滚动，鼠标滚轮、触控板和长页面表格不能被窗口拖动逻辑拦截。
- [ ] 语言跟随系统，同时保留手动中英文切换；切换后训练模式、帮助文本和错误提示也必须翻译。
- [ ] 内存状态显示 Orbit 自身占用和电脑剩余内存，不把主要占用伪装成不可解释的 Python 进程。
- [ ] 只保留一个正式 Orbit App/Logo 入口；更新或解压安装包后检查 `/Applications/Orbit.app` 是否只有一个有效版本。

## 发布与更新闭环

- [ ] 每次功能更新都要同步版本号、Git 提交、正式 Git tag 和 GitHub Release，不能只推送 main。
- [ ] Release 必须实际包含 macOS universal、Windows x64/ARM64、Linux x64/ARM64 资产；CI 任一平台失败都不能宣称发布完成。
- [ ] 发布前先跑测试、构建本机 App、验证签名/压缩包和版本号，再上传 GitHub。
- [ ] 本机更新后核对 App 版本、本地运行时版本、`/api/health`、`/api/system` 和后台 API；训练进行中不能强制重启或破坏 checkpoint。
- [ ] macOS App 内更新不能只更新 `~/.orbit/runtime`：必须同时下载并替换 `/Applications/Orbit.app`，重新打开后核对可见 App 版本、运行时版本和 API 版本；项目源码运行时优先读取当前 `pyproject.toml`，避免旧 dist-info 造成假版本。
- [ ] 发布前统一核对 `pyproject.toml`、macOS plist、Windows csproj、Linux package/package-lock 的版本号；五个平台资产和已安装 App 必须对应同一个 Release tag。
- [ ] 自动更新必须在设置中可开关，并兼容跨版本迁移；更新失败要在 App 内显示原因和回滚/重试状态。
- [ ] 左下角必须同时提供“检查更新”和“立即安装”；前者不能承担安装动作，后者必须调用安装接口、显示下载/排队/失败状态。训练中安装只能排队到安全 checkpoint 后，不能强制终止训练。

## 最小回归命令

```sh
.venv/bin/python -m pytest -q
.venv/bin/python -m orbit.web --help
curl -fsS http://127.0.0.1:8765/api/health
curl -fsS http://127.0.0.1:8765/api/system
```

发布前还要人工打开“训练”页，切换到微调，确认基础模型自动出现；再切回预训练，确认基础模型被清空且按钮状态正确。
