# Orbit 300M–38B 全模型规模推荐

这是训练页推荐器的解释文档。App 会根据模型规模、设备、可用内存、训练方式、人工文献字数和 AI 辅助样本数重新估算；下表是无额外训练目标文字时的基线，不是保证值。

## Token 预算与样本数

旧版把 300M～38B 都写成几百到几千个样本，这是不正确的：它把一个运行上限
误当成完整预训练语料。现在 App 按 Chinchilla 的约 20 token/参数基线计算总量，
并把样本数换算成当前教师样本平均约 6,750 token 的估计值：

| 模型 | 预训练参考 token（约 20/参数） | 参考独立样本（约 6,750 token/条） | 数据丰富度论文对照（约 37/参数） |
| --- | ---: | ---: | ---: |
| 300M | 60 亿 token | 888,889 条 | 约 111.1 亿 token |
| 1B | 200 亿 token | 2,962,963 条 | 约 370.4 亿 token |
| 3B | 600 亿 token | 8,888,889 条 | 约 1111.1 亿 token |
| 7B | 1400 亿 token | 20,740,741 条 | 约 2592.6 亿 token |
| 14B | 2800 亿 token | 41,481,482 条 | 约 5185.2 亿 token |
| 38B | 7600 亿 token | 112,592,593 条 | 约 1.407 万亿 token |

300M、1B、3B 的参考样本数可以在一轮内表示；7B 及以上会超过 Orbit 每轮
10,000,000 条的教师安全上限，必须分多轮生成、查看、去重和审核。这个上限是
防止 API 费用、磁盘和内存失控，不是论文规定的训练规模。真实文献的平均 token
数不同，App 会根据实际生成统计重新计算；人工语料应直接看 token 预算，不把字符数
和 token 数混为一谈。

“省时间 / 省内存 / 平衡 / 效果优先”只改变当前实验的序列长度、有效 batch、
checkpoint 和设备配置。论文没有规定四个通用的固定步数；App 用当前语料 token、
序列长度、batch、梯度累计和遍历次数计算 optimizer steps，并在选项里同时显示
“本轮样本 / 完整参考样本”。

## 本机内存边界

| 模型 | 估算训练内存 | 24GB Mac 建议 |
| --- | ---: | --- |
| 300M | 约 9.1GB | 可作为本机起点，仍需保留系统安全余量 |
| 1B | 约 32.5GB | 不建议本机，生成远程 GPU 任务包 |
| 3B | 约 92.9GB | 远程 GPU |
| 7B | 约 226.6GB | 远程 GPU |
| 14B | 约 446.2GB | 多 GPU / 远程 GPU |
| 38B | 约 1,218.1GB | 分布式远程 GPU |

模型规模只是架构大小，不代表已经拥有相应规模的预训练知识。大模型从零预训练需要大量高质量 token 和对应算力，不能用几百个样本冒充完整预训练。

## 预训练与微调的研究型建议

- 预训练第 1～N 次：文献、教材、技术资料、代码和代码注释为主体，先去重和质量过滤，再加入少量结构化任务、对话和身份。按总 token 与主题覆盖率规划，不要只按样本条数重复小语料。
- 微调：选择已有 checkpoint，动态混合专业文献、明确输入→输出的分类/NER/代码/SQL/摘要任务和高质量指令对话。先用较低学习率和 1～3 个数据遍历并保留验证集，再按验证弱项补样，不使用固定百分比。
- 参数选择按“省时间 / 省内存 / 效果优先”比较：序列长度和 batch 主要增加内存与单步时间；梯度累计主要增加总时间而较省内存；步数直接增加训练时间；学习率主要影响收敛、遗忘和后续所需步数。
- 研究依据与完整人工/AI 语料分工见：[训练数据质量与参数建议-研究依据.md](训练数据质量与参数建议-研究依据.md)。

## 人工和 AI 同时训练

可以。用户填写或导入的人工文献、代码和任务会与教师 AI 生成的语料合并，放入同一次本机训练；AI 生成的原文仍单独保存，训练历史可以查看。预训练保持“多文献/代码为主、结构化任务和少量对话/身份为辅”；微调按验证结果动态混合专业文献、单轮任务和高质量对话。

人工样本数不是固定输入框，而是由文本长度、序列长度和有效 batch 估算。输入的文字太少时，App 应显示“语料覆盖不足”提醒并给出建议字数；AI 辅助样本数仍显示为独立数量。

## 选择建议

- 300M 首次验证：若只是验证流程，可选“省内存”并使用少量人工/AI 语料，App 会明确标记为实验；若按从零预训练研究基线规划，则目标约 60 亿 token、约 888,889 条当前平均长度样本，不应把几百条样本宣传为完整预训练。
- 300M 编程聊天方向：以代码、代码注释、技术文献和结构化代码/SQL 任务为主，最后加入少量对话和 Orbit 身份样本。
- 预训练第 2～N 次：选择上一轮 Orbit checkpoint，追加新的文献主题，不要反复复制同一小数据集。
- 微调：选择已有 Orbit checkpoint，根据领域目标和验证集弱项动态混合专业文献、标注任务与高质量指令对话；不要把外部 Qwen/Llama 权重当作 Orbit checkpoint。
- 如果内存不满足推荐值，App 应禁用本机开始按钮并说明原因，只生成远程 GPU 任务包，不强行占满电脑。
