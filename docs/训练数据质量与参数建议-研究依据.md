# Orbit 训练数据质量与参数建议（研究依据）

Orbit 必须把“预训练”和“微调”当成两种不同的训练任务，不能只换一个标题。

## 预训练：学习语言、知识和代码分布

适用场景：预训练第 1 次从随机权重开始；第 2～N 次从上一轮 Orbit checkpoint 继续训练。

人工语料优先准备：清洗、去重后的书籍、教材章节、技术文档、科学资料和事实材料；代码、代码注释、测试、错误分析和可运行示例；按目标场景平衡中英文；最后再加入少量结构化任务、对话和 Orbit 身份样本。

不写死未经实验支持的类别百分比。初始混合应覆盖通用语言与世界知识、教材/科学/推理、数学、代码/技术资料和结构化任务，并只保留少量对话/身份尾部；具体权重依据去重后的 token 数、来源质量、目标领域覆盖和独立验证集结果迭代。真正的大规模预训练按总 token、主题覆盖和验证集规划，不能把几十个样本重复几百遍当成通用预训练。

AI 辅助在预训练中负责生成基础认知、通用语言表达、常见编程模式、基础任务和少量身份样本；人工内容负责用户自己的项目、产品和领域知识。两者可以在一次训练中合并，但必须保留各自的来源记录。

## 微调：学习领域能力、任务格式和交互行为

适用场景：必须选择已有 Orbit checkpoint 或经过真实兼容性验证的基础模型。外部 Qwen/Llama 权重不能仅凭文件名直接当作 Orbit 从零训练模型。

微调的 M/B 档位必须锁定为基础模型的原始规模。用户不能手动改，AI 辅助也不能改；如果想换规模，必须另选一个对应规模的基础模型。

人工语料优先准备：目标领域专业文献、产品资料、术语、事实和规范流程；明确输入→输出的分类、情感分析、NER、代码/SQL、摘要和扩写任务；高质量指令对话；训练集与验证集分开。具体配比由验证集表现和目标任务决定。

微调不采用固定百分比。初始应同时保留通用知识、领域文献、结构化任务、代码/数学、对话表达和身份安全样本，再依据验证集自动补足效果较差的类别。微调先从较低学习率、约 1～3 个数据遍历开始；验证集没有变好时不要继续增加步数。样本可以增加，但必须先去重和质检。

AI 辅助在微调中负责基础认知、通用编程模式、基础任务和对话格式；人工内容负责用户希望模型记住的专业知识。若人工内容为空，App 应提示微调会缺少用户的领域知识，而不是静默伪造训练数据。

## App 应给出的不合理配置提醒

- 预训练只有几十个短样本，却设置数百步：提示会重复记忆小数据集，建议增加多主题文献或改为微调。
- 微调没有基础模型：禁用开始按钮，并说明必须先选择 checkpoint。
- 微调样本很少但步数、梯度累计很大：提示过拟合风险，建议先使用 500～1,000 条高质量样本或降低到约 60～120 步。
- 只有对话、没有文献或结构化任务：预训练提示语料不是文献优先；微调提示领域知识和任务格式不足。
- 没有验证集、内容重复、存在乱码、隐私、密钥或无法核验的事实：提示先清洗、去重、过滤并保留验证集。
- 把“样本数”当成“步数”：明确说明样本是一篇独立文献/任务，步是一次优化器更新；二者由 token 数、序列长度、batch、梯度累计和数据遍历次数关联。
- 300M 随机权重只给几十万或几百万 token：标记为流程实验，显示相对约 60 亿 token 参考目标的覆盖率，不能承诺正常聊天。
- 教师 AI 返回的字符数、字节数和 token 数混写：分别显示。当前 Orbit 的 `orbit-byte-v1` 中一个 UTF-8 字节等于一个训练 token，这不是通用 BPE token 计数。

## 数据边界、去重和验证

- AI 辅助生成的每条样本必须有机器可解析的开始/结束边界；不能靠空行或 Markdown 标题猜测样本数。
- 进度按实际通过检查的独立样本累计，而不是按请求数量或教师自报数量累计。格式不完整、语言不符、乱码、控制字符、完全重复和近重复样本不能进入训练集。
- 至少按样本确定性隔离 5% 验证集，防止同一篇文献的随机窗口同时进入训练与验证。当前版本只负责隔离并保存验证集；尚未实现自动 validation loss/early stopping 时必须如实说明。
- 教师提示里的“事实谨慎”只能降低风险，不能证明内容真实。没有独立来源核对或另一套审核器时，状态必须显示“事实尚未独立审核”。
- 人工与 AI 内容合并时，训练进程必须实际读取合并后的文件；不能只在界面保存合并文件，却仍把旧的单一文本参数交给训练 worker。

## 300M 的 token 与更新量级

Chinchilla 的 compute-optimal 结论可作为从零预训练的量级参考：约每参数 20 个训练 token。按名义 300M 参数估算约为 60 亿 token。以 Orbit 当前教师样本实测平均约 6,750 UTF-8 字节计算，约需 888,889 篇同量级且真正独立的文献。若序列长度 1,024、Batch 1、梯度累计 8，则一次覆盖约需 732,422 次优化器更新。它不是质量保证，也不能替代 tokenizer、模型架构、数据版权、数据质量和硬件实验。

实际聊天能力优先走“已预训练基础模型 + SFT”，而不是在普通用户电脑上从随机 300M 权重开始。SFT 的研究起点应是高质量、去重、覆盖目标任务的约 1,000 条精心筛选样本（LIMA 的研究基线），再根据验证集弱项扩展到 10,000 条或更多；这不是对所有领域的硬性最低值。序列长度、Batch 1、梯度累计和学习率由基础模型与设备推荐，通常从低学习率、1 个数据遍历开始，只有验证集继续改善才增加遍历。优化器更新数按实际 token 覆盖计算，不能把固定的 12,500 步写成通用答案。教师 AI 每轮最多生成 10,000,000 条，超过时分轮生成、审核并训练。

### 全模型规模 token 基线

按 Chinchilla 的约 20 token/参数规划基线，名义档位的从零预训练参考是：300M 约
60 亿、1B 约 200 亿、3B 约 600 亿、7B 约 1400 亿、14B 约 2800 亿、38B 约
7600 亿 token。这个基线用于规划数据规模，不是保证模型能力，也不规定固定样本数
或固定 steps。Llama 3 的报告约 15T/405B（约 37 token/参数）是数据丰富度的
一个规模实例，Orbit 仅作对照显示。人工语料按真实 tokenizer/token 统计，不能把
字符、字节、样本和步数混写。

## 参数解释

- 学习率：预训练可使用较高起点；微调使用更低起点，避免破坏已有能力。它通常不显著改变单步耗时，却会显著影响收敛和遗忘。
- 序列长度：影响每步内存和时间；长文档需要更长序列，内存不足时优先降低它。
- batch size：提高有效吞吐，但增加激活内存；内存紧张时保持 1，并用梯度累计替代。
- 梯度累计：提高有效 batch，通常比直接提高 batch 更省内存，但会增加时间。
- 步数：直接增加训练时间；预训练不能只靠步数弥补语料质量不足，微调要防止过拟合。
- checkpoint 间隔：不改变理论每步时间，但会增加保存时的磁盘写入和等待。

## 研究依据

- [Training Compute-Optimal Large Language Models（Chinchilla）](https://arxiv.org/abs/2203.15556)：模型规模必须和训练 token 预算一起规划。
- [The FineWeb Datasets](https://arxiv.org/abs/2406.17557)：去重、质量过滤和高教育质量文本会影响训练数据价值。
- [Dolma](https://arxiv.org/abs/2402.00159)：开放预训练语料需要记录来源、清洗、去重和混合过程。
- [Deduplicating Training Data Makes Language Models Better](https://arxiv.org/abs/2107.06499)：训练/验证重叠与重复数据会影响记忆和评估可靠性。
- [Textbooks Are All You Need](https://arxiv.org/abs/2306.11644)：教材式代码和练习对小型代码模型有帮助。
- [TinyStories](https://arxiv.org/abs/2305.07759)：受控、高质量的简化语料可让很小的语言模型学习连贯生成，但不等于获得通用世界知识。
- [The Llama 3 Herd of Models](https://arxiv.org/abs/2407.21783)：大规模预训练依赖数据混合、过滤、去重和后训练，而不是只增加重复步数。
